02 overview

When I was brainstorming different project ideas, my mind stumbled upon this specific one. I didn't know about many sites offering this functionality while being actually useful.

Wherelse - because "Where else would you look" - is a webapp letting users compare any two services/Saas. Its practicality lies in the information the user recieves ranging from feature overviews, usecase demonstrations to user reviews.

Under the hood a simple yet effective web scraping system is designed to obtain the most relative information (such as reviews or recommendations). An AI model then synthesises the information into a structured comparison while using as little of its own information as possible. This prevents AI hallucinations and guarantees authenticity and factuality to the result.

To ensure cost-effectivness the backend saves already generated comparisons into the app's database to avoid repeating the same user requests. To expand on this, the app utilizes threading and keeps track of ongoing generations so multiple users could benefit from the same AI API call. This further reduces repetitions and in the long run the costs of token usage.

Since I mainly focus on backend, I worked with Claude to achieve a satisfying frontend.

Currently this app is hosted on Render and due to cost limitations, the server spins down with inactivity. Please wait for about 50 seconds until the server and the app itself wakes up.

04 challenges & what i learned

Building a web app from the ground up!

AI API Integration

My main goal for this project, besides building an app from 0, was to grasp the concept of working with an AI model. I learned API calling and AI web scraping.

Threading

In the process of building Wherelse I stumbled upon a simple yet new problem of loading screens. For this reason, I had to learn the use of threading to sideline a process and in the meantime display a loading screen.

Efficent token usage

Wherelse uses a system where if several users enter the same query simultaneously, the backend calls the AI only once resulting in smaller token usage. In addition, Wherelse saves already processed comparisons into its database and later on retrieves them from there.
